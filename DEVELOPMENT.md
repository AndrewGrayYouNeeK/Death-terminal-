# DeathTerminal Development Guide

This document tracks development status and priorities for the DeathTerminal desktop terminal emulator.

## Project Overview

DeathTerminal is a Zig-based, GPU-accelerated terminal emulator. AI suggestions, SSH tunneling, and Lua scripting are planned. It is a **native desktop application** — not a web app.

## Architecture

```
PTY ↔ Terminal Core ↔ Renderer (Vulkan)
           ↓
        AI Engine (HTTP/JSON)
           ↓
        Lua Scripting
```

## Module Status

| Module | Path | Status |
|--------|------|--------|
| Terminal core | `src/terminal/` | PTY (`pty.zig`), VT500 parser (`ansi_parser.zig`), xterm-compatible emulation (`terminal.zig`, tests in `vt_test.zig`), key/mouse/paste encoding (`input.zig`), palette (`color.zig`) — see [docs/VT_SUPPORT.md](docs/VT_SUPPORT.md) |
| Scrollback | `src/terminal/scrollback.zig` | Functional; UTF-8 text/search |
| Unicode | `src/terminal/unicode.zig` | Column width (0/1/2) from generated Unicode 15.1 tables |
| Event loop | `src/app/event_loop.zig` | Headless + native GUI; exits when the shell exits |
| Vulkan renderer | `src/renderer/` | Instance/device (`vulkan_renderer.zig`), swapchain acquire/present (`gpu_present.zig`), SPIR-V glyph pipeline (`text_pipeline.zig`), CPU fallback (`software.zig`) |
| Window | `src/platform/window.zig` | Wayland, X11, Win32 + HiDPI scale; keys/mouse/focus events through `events.zig` |
| AI autocomplete | `src/ai/` | Stub (planned: OpenAI-compatible HTTP/JSON, default local Ollama) |
| SSH tunneling | `src/ssh/` | Stub (planned: libssh2) |
| Lua scripting | `src/scripting/` | Stub (Lua not linked yet) |
| Configuration | `src/config/` | Reads `~/.config/death-terminal/config.txt` with flat `key = value` lines (`rows`, `cols`, `ai_enabled`, `ai_endpoint`, `scrollback_lines`, `font`, `font_family`, `font_size`, `line_height`, `font_ligatures`). `config.example.lua` is the target format for the Lua milestone and is not read yet. |

## Build Requirements

- Zig 0.13+
- Vulkan SDK (`libvulkan-dev` on Linux)
- Mesa Vulkan ICD (`mesa-vulkan-drivers`) for instance/device tests without a GPU
- X11 (`libx11-dev`) and/or Wayland (`libwayland-dev`, `libxkbcommon-dev`)
- Fonts: `libfreetype-dev`, `libharfbuzz-dev`, `libfontconfig-dev` (Linux). Fallback fonts for tests/screenshots: `fonts-noto-cjk`, `fonts-noto-color-emoji`
- Lua 5.4 (not required yet; needed once scripting lands)

```bash
zig build          # Build
zig build run      # Run
zig build test     # Test
./dev.sh run       # Dev helper
```

## Development Phases

### Phase 1 — Terminal Core (partial)
- [x] PTY creation and shell spawning
- [x] ANSI/VT100 escape sequence parser
- [x] Cell buffer and cursor control
- [x] Scrollback buffer
- [x] PTY on Unix (Linux/macOS)
- [ ] PTY on Windows (ConPTY)
- [x] UTF-8 decoding, wide characters, combining marks (`src/terminal/unicode.zig`; width tables generated by `tools/gen_unicode_width.py`)
- [x] Scroll regions, alternate screen, insert/delete, 256/true color, mouse, bracketed paste, focus events, DA/DSR

### Phase 2 — Rendering
- [x] Vulkan module structure
- [x] Vulkan function loading
- [x] Instance + optional logical device
- [x] Window/surface creation (X11, Wayland, Win32)
- [x] Swapchain blit present (software framebuffer → GPU)
- [x] Text rendering pipeline (SPIR-V glyphs)
- [x] HiDPI cell scaling

### Phase 3 — Application Layer
- [x] Main event loop with PTY polling
- [x] Signal handling (SIGINT, SIGTERM)
- [x] Configuration file loading
- [x] Headless terminal mode (no window)
- [x] Window resize (swapchain recreate + PTY winsize)
- [x] Native GUI backends (Wayland / X11 / Win32)

### Phase 4 — AI Integration
- [ ] OpenAI-compatible HTTP/JSON client (default: local Ollama)
- [ ] Context gathering and sanitization
- [ ] Ghost-text suggestion UI (Tab to accept)

### Phase 5 — SSH & Scripting
- [ ] libssh2 integration
- [ ] Lua 5.4 bindings
- [ ] Plugin system
